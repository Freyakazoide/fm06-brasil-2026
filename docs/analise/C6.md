# Ficha C6 — Instalações e base do clube

- Quem analisou / data: Codex, 2026-10-22
- Ferramenta: Capstone 5.0.9 + pefile, `fm.exe` 6.0.2 original
- Função principal: `00a31c70`, trecho `00a325af`–`00a32750` (`CLUB_ler`)

## Resumo

O trecho indicado não lê 18 bytes escalares em sequência. Ele lê uma presença opcional,
dois bytes e três subobjetos; depois consome uma data descartável em versões novas. Isso
indica que os 18 bytes vistos no arquivo pertencem a uma estrutura anterior ou a um dos
subobjetos, e não podem ser mapeados somente contando chamadas a partir de `00a325af`.

## Respostas às perguntas da ficha

1. A ordem do trecho final é a tabela acima.
2. Não há base para afirmar quais bytes são CT, instalações ou captação. Os candidatos
   mais plausíveis no fim são `+0xed/+0xee` e os subobjetos, mas isso precisa de referências
   de tela/geração de jovens.

## Trechos importantes

```text
if (versao >= 0x103) { ler_u8(club+0xed); ler_u8(club+0xee); }
if (versao >= 0x10a) { ler_obj(club+0x1a0); ler_obj(club+0x1a8); ler_obj(club+0x1b0); }
```

## Dúvidas e o que não deu para ver

O achado dos “18 bytes” precisa ser realinhado com o começo exato do registro ou com o
leitor do subobjeto anterior. Não gravar as notas 1–20 no banco ainda.
