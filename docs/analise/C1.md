# Ficha C1 — Patrocínio

- Quem analisou / data: Codex, 2026-10-22
- Ferramenta: Capstone 5.0.9 + pefile, `fm.exe` 6.0.2 original
- Função principal: `00aa6ec0` (`SPONSOR_ler`)

## Resumo

O registro tem exatamente cinco campos diretos: objeto, `u8`, objeto, `u8`, `u8`. Não há
nenhum inteiro de 32 bits no registro; portanto, um valor monetário anual não está gravado
diretamente aqui como número simples. Os objetos têm 12 bytes no objeto `SPONSOR`, formato
compatível com os objetos de texto usados pelo jogo, mas a semântica dos três bytes ainda
não foi fechada.

## Respostas às perguntas da ficha

1. A ordem e os tipos estão confirmados. Os dois objetos são provavelmente textos. Ainda
   não é seguro chamar um de empresa e o outro de tipo sem rastrear as telas.
2. O leitor recebe um pai e anexa o registro em `parent + 0x54`; ainda não foi demonstrado
   se esse pai é clube, nação ou o contêiner global do banco.
3. O valor não está neste registro como `u32`. Se existir um valor por clube, ele é
   calculado/obtido em outro objeto ou codificado indiretamente por um dos bytes.

## Trechos importantes

```text
00aa6ece ler_objeto -> +0x1c
00aa6edd ler_u8     -> +0x28
00aa6eec ler_objeto -> +0x2c
00aa6efb ler_u8     -> +0x38
00aa6f0a ler_u8     -> +0x39
```

## Dúvidas e o que não deu para ver

Falta cruzar `+0x1c/+0x2c/+0x28/+0x38/+0x39` com o painel de receitas. Não usar ainda a
planilha de patrocinadores para escrita binária.
