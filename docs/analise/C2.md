# Ficha C2 — Suspensões no começo do jogo

- Quem analisou / data: Codex, 2026-10-22
- Ferramenta: Capstone 5.0.9 + pefile, `fm.exe` 6.0.2 original
- Função principal: `00aa71e0` (`STARTING_BAN_ler`)

## Resumo

O formato atual tem quatro campos, não três: `u32`, objeto serializado, `u8` e, em bancos
de versão `>= 0x11c`, outro `u8`. O registro vai para uma coleção global em `parent + 0xb0`.

## Campos lidos, em ordem

| # | Endereço da instrução | Lê | Vai para | O que acho que é | Certeza | Por quê |
|---|---|---|---|---|---|---|
| 1 | `00aa71ee` | u32 | `this + 0x1c` | referência de pessoa | média | tamanho e papel esperado; uso posterior ainda não fechado |
| 2 | `00aa71f8` aprox. | objeto, método `+0x14` | `this + 0x24` | data ou referência de competição | baixa | leitura virtual confirmada, classe do subobjeto não identificada |
| 3 | `00aa720b` | u8 | `this + 0x20` | quantidade de jogos | média | único byte obrigatório após as referências |
| 4 | `00aa7231` | u8 | `this + 0x2c` | flag/escopo adicionado depois | baixa | existe só a partir da versão `0x11c` |

| Endereço | Condição ou lista | O que fica dentro |
|---|---|---|
| `00aa7220` | versão `>= 0x11c` | lê `this + 0x2c` |
| `00aa7270` | coleção | anexa em `parent + 0xb0` |

## Quem chama / de onde vem

| Endereço | Função | O que faz com isto |
|---|---|---|
| `009edc8f` / `009edd74` | registro/fábrica | referencia a vtable `010e2144` |

## Respostas às perguntas da ficha

1. `+0x1c` é forte candidato a UID/índice de pessoa, mas ainda não está confirmado por
   uma busca de pessoa.
2. `+0x24` é um objeto serializado; não foi possível decidir entre data e competição.
3. `+0x20` é forte candidato ao número de jogos.
4. Os registros ficam numa lista em `parent + 0xb0`, aparentemente uma tabela global do
   banco, não dentro do jogador.

## Trechos importantes

```text
ler_u32(stream, this+0x1c)
(this+0x24)->ler(stream)
ler_u8(stream, this+0x20)
if (versao >= 0x11c) ler_u8(stream, this+0x2c)
```
